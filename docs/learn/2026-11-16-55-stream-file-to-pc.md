# 큰 파일 PC 직접 저장 (이슈 #55)
> 이슈 #55 · 한 줄 요약: 파일을 서버 메모리에 모으지 않고, 조각을 받는 PC 쪽으로 그대로 흘려보내 PC 디스크에 바로 쓴다.

## 어떤 문제였나
서버는 파일 전체를 메모리에 모았다가 보내서, 큰 파일(700MB 등)은 서버 메모리 한도(`MEM_MB`)를 넘어 보낼 수 없었다. 메모리를 키우는 것은 해결이 아니었다 — 합칠 때 두 배가 필요하고 서버가 죽을 수 있다.

## 새로 쓴 기술
### 1. 조각 중계 (pass-through)
- **개념**: 서버가 데이터를 저장하지 않고, 들어오는 조각을 곧바로 다른 연결(받는 쪽의 응답)로 내보내는 방식.
- **왜 필요했나**: 메모리 한도와 무관하게 큰 파일을 보내려면 서버가 파일을 쌓지 않아야 한다.
- **이 코드에서는**: `stream/server.js` 의 `/api/stream/chunk` 가 조각 하나를 받는 쪽 응답에 `write` 하고, 끝나면 응답을 닫는다. 조각은 한 번에 하나만 메모리에 있다.
- **주의할 점**: 받는 쪽이 끊기면 그 파일은 완성되지 않는다. 그래서 받는 쪽 응답을 `destroy` 해서 "덜 받았다"는 것을 알 수 있게 했다 (정상 끝이 아니면 파일을 완성된 것처럼 두지 않는다).

### 2. backpressure (밀림 전달)
- **개념**: 받는 쪽이 느리면 보내는 쪽에 그 속도를 알려 기다리게 하는 것.
- **왜 필요했나**: 받는 쪽 버퍼가 차도 서버가 계속 받으면 메모리에 쌓인다.
- **이 코드에서는**: `res.write(buf, callback)` 의 콜백이 실제로 내보낸 뒤에 호출되므로, 그 전까지 보내는 쪽의 조각 요청 응답을 보내지 않는다. 보내는 쪽은 응답을 받은 뒤 다음 조각을 올린다.
- **주의할 점**: 루프백 버퍼가 크면 이 시험 PC 에서는 밀림이 거의 0ms 로 나온다. 그래서 시험은 "밀림이 생기면 기다린다"를 검사하지 않고 측정값만 보여 준다.

### 3. 받는 쪽 응답을 스트림으로 (Content-Length + flushHeaders)
- **개념**: `GET` 응답 하나를 오래 열어 두고 그 안으로 파일을 흘려 넣는 것.
- **왜 필요했나**: 헤더가 바로 나가지 않으면 받는 쪽은 읽기를 시작하지 못하고 연결이 끊겨 보인다 (시험에서 "other side closed" 로 드러남).
- **이 코드에서는**: `res.writeHead` 뒤 `res.flushHeaders()` 로 헤더를 바로 보낸다.

### 4. File System Access API (showSaveFilePicker)
- **개념**: 브라우저가 저장 위치를 고르게 하고, 파일을 조각씩 디스크에 쓰게 하는 API.
- **왜 필요했나**: 메모리에 전부 모으지 않고 PC 디스크에 쓰려면 이 방법이 필요하다.
- **이 코드에서는**: `public/stream.js` 의 `receiveFile` 이 "받기" 클릭 안에서 저장 창을 열고 `createWritable()` 로 조각마다 `write` 한다.
- **주의할 점**: 사용자 동작(클릭) 안에서 바로 열어야 한다. 지원하지 않는 브라우저에서는 받을 수 없으니 안내만 한다.

## 어떻게 시험했나
- `stream.test.js` (20): 제안 한도(413), 한 번에 한 파일(409), 받는 쪽 준비 전 조각(409), 조각 순서·끝(done), 받은 내용의 sha256 일치, 취소·받는 쪽 끊김(410), 끝난 뒤 상태(gone).
- 메모리 한도 시험: `MEM_MB=10` 으로 띄우고 `STREAM_TEST_MB=60` — 기존 방식이라면 507 로 막혔을 크기가 끝까지 흐른다.
- `stream-ui.test.js` (13): 실제 화면. 시험에서는 `showSaveFilePicker` 를 메모리에 받는 가짜로 바꿔 해시를 비교했다 (Edge 는 실제 저장 창을 자동으로 열 수 없어서).

## 더 공부할 키워드·자료
- Node.js Streams: `writable.write` 의 반환값과 `drain` 이벤트, `res.write(chunk, cb)`
- HTTP chunked 전송과 Content-Length, `flushHeaders`
- File System Access API (MDN: `window.showSaveFilePicker`, `FileSystemWritableFileStream`)
