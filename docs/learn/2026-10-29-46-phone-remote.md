# 컴퓨터로 휴대폰 원격 조종: MediaProjection + 접근성 서비스

> 이슈 [#46](https://github.com/esstional-tool/text-tunnel/issues/46) · 2026-10-29
> PC 가 폰 화면을 보고 조종하려면 폰 쪽에 **앱**이 필요하다. 서버와 PC 보는 화면은 PC 원격 구조를 그대로 재사용하고, 폰 앱이 "폰 에이전트"가 된다.

## 왜 웹(PWA)으로는 안 되나

- 안드로이드 브라우저는 **화면 공유(`getDisplayMedia`)를 지원하지 않고**, 다른 앱에 터치·키 입력을 넣을 수도 없다(보안 모델).
- 그래서 폰에 설치하는 앱이 (1) 화면을 캡처해 서버로 보내고 (2) 서버가 전달한 입력을 터치로 바꿔 넣는다. 아이폰은 OS 가 원격 조종을 허용하지 않아 불가능하다.

## 구조 (PC 에이전트와 같은 프로토콜)

```
폰 앱 ── POST agent/join {key, name, platform:'android'} ──▶ 서버 ◀── PC 브라우저 (같은 key, PIN)
폰 앱 ◀─ SSE: viewers · auth(PIN) · input · profile ──────── 서버
폰 앱 ── POST frame (JPEG) ──────────────────────────────▶ 서버 ── frame 알림 ─▶ PC 브라우저
```
서버에 새로 생긴 것은 둘뿐이다: 에이전트가 `platform` 을 알림(보는 화면이 폰 도구줄을 보이려고), 폰용 입력 종류 `n`(뒤로·홈·최근·알림)·`s`(글자 보내기)·`k.ch`(입력된 글자). 서버는 허용된 모양만 걸러 전달한다.

## 새로 쓴 기술

### 1. MediaProjection: 사용자가 허용한 화면 캡처
- 앱이 `createScreenCaptureIntent()` 로 시스템 허용 창을 띄우고, 사용자가 "지금 시작"을 누르면 토큰(결과 Intent)을 받는다. 그것으로 `VirtualDisplay` 를 만들어 `ImageReader` 에 그림을 받는다.
- 안드로이드 14+ 규칙: **포그라운드 서비스(타입 mediaProjection)를 먼저 시작**해야 `getMediaProjection` 이 되고, 가상 화면을 만들기 **전에 콜백을 등록**해야 하며, 한 토큰으로 **가상 화면을 한 번만** 만들 수 있다(크기가 바뀌면 `resize` + `setSurface`).
- 가상 화면은 **화면이 바뀔 때만** 새 그림을 준다 → 마지막 그림을 들고 있다가 새 그림이 없으면 그것을 쓴다. 화면이 같으면(픽셀 비교) 보내지도 않는다.

### 2. 접근성 서비스 + `dispatchGesture`: 터치 주입
- 접근성 서비스는 사용자가 설정에서 직접 켜야 한다(안드로이드 13+ 는 사이드로드 앱에 "제한된 설정 허용"이 먼저). `canPerformGestures=true` 면 `dispatchGesture(Path…)` 로 탭·길게·스와이프를 넣을 수 있다.
- PC 의 마우스 이벤트를 터치로 **번역**한다: 누름(d)~뗌(u) 사이의 경로를 모아, 거의 안 움직였으면 탭(0.5초 넘으면 길게), 움직였으면 스와이프. 오른쪽 버튼=뒤로(`GLOBAL_ACTION_BACK`), 가운데=홈. 휠은 화면 가운데를 위아래로 미는 스와이프.
- 글자: 포커스가 있는 입력칸(`findFocus(FOCUS_INPUT)`)의 **커서 위치**에 `ACTION_SET_TEXT` 로 끼워 넣고 `ACTION_SET_SELECTION` 으로 커서를 옮긴다. 한글 조합은 브라우저→폰으로 키 코드를 보내서는 안 되므로 PC 쪽 "글자 보내기" 칸의 완성된 글자를 통째로 보낸다.

### 3. 같은 안전 원칙을 폰에도
PIN 은 폰 주인이 정하고 **폰이 직접 해시(PBKDF2)로 확인**(5번 틀리면 10분 잠금), 조종은 **별도 허용(기본 꺼짐)** + 접근성 서비스가 켜져 있을 때만, 화면 공유 중 **알림이 항상 떠 있고 "중지/조종 끄기" 단추**가 있다. 폰이 PIN 을 확인해 준 사람의 입력만 적용(서버를 믿지 않고 폰도 확인).

### 4. 외부 라이브러리 없는 안드로이드 앱
AndroidX·OkHttp 없이 `HttpURLConnection`(POST + SSE 줄 읽기)·`org.json`·`SharedPreferences` 만 썼다. 서버·PC 쪽의 "의존성 0" 원칙과 같다. Gradle 빌드는 Android Studio 에 들어 있는 JDK·SDK 로 첫 빌드 약 1분.

## 시험 / 남은 일
- **자동 시험**: 서버(폰용 입력 검사 9), PC 보는 화면(폰 도구줄 8) 통과. 폰 앱은 컴파일 성공.
- **에뮬레이터 시험(`tests/phone-agent.test.js`)은 아직 못 돌렸다** — 이 PC 의 SDK 가 이미지가 빈 상태라 새로 받다가(그 과정에서 curl 두 개가 같은 파일을 덮어써 손상 → sha1 로 발견) 병합 시점에 실행하지 못했다. 이 시험은 앱을 가상 폰에 깔아 프레임 수신·탭·스와이프·글자·홈·조종 끄기·기록까지 확인한다. **실제 폰 확인도 필요.**
