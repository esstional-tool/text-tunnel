# 받은 파일을 다른 앱으로 공유하기: Web Share API

> 이슈 [#35](https://github.com/esstional-tool/text-tunnel/issues/35) · 2026-10-23
> text-tunnel 로 받은 PDF·사진·동영상을 카카오톡 등으로 바로 내보내고 싶다는 요청. **카카오 SDK 대신 기기 기본 공유창**을 썼다.

## 왜 카카오 SDK 가 아니었나

카카오 공유(Kakao Link)는 외부 스크립트·앱 키·도메인 등록이 필요하고, 내용이 카카오 서버를 거친다. 이 앱의 원칙(외부 서비스 없음, 흔적 없음)과 맞지 않는다. **Web Share API** 는 브라우저가 OS 의 공유창을 띄워 주고, 거기서 카카오톡을 포함한 설치된 앱을 사용자가 고른다. 앱이 외부로 보내는 것은 없다.

## 새로 쓴 기술

### 1. `navigator.share({ files })` 와 `navigator.canShare`

- **개념**: 파일을 `File` 객체로 만들어 `navigator.share({ files: [file] })` 에 넘기면 OS 공유창이 뜬다(Android·iOS·Windows 의 Edge/Chrome). `navigator.canShare({ files })` 로 이 기기·이 형식이 공유 가능한지 미리 물을 수 있다.
- **이 코드에서는**: 시작할 때가 아니라 버튼을 만들 때마다 `canShareFiles()`(작은 더미 PDF 로 `canShare` 시험)를 호출해, 지원하지 않으면 버튼을 `hidden`. 공유 직전에는 실제 파일들로 다시 `canShare` 를 물어 "이 파일은 공유할 수 없어요"를 구분한다.
- **주의**: `text` 를 같이 넘기면 일부 앱(카카오톡 등)이 파일을 버리고 글만 받는 일이 있어 **파일만** 넘긴다. 사용자가 공유창을 닫으면 `AbortError` — 오류가 아니므로 조용히 끝낸다.

### 2. 사용자 동작 허용(transient activation)의 만료

- **개념**: `navigator.share` 는 클릭 같은 **사용자 동작 직후**에만 호출할 수 있다. 이 허용은 몇 초 뒤 만료된다(`NotAllowedError`). 그런데 큰 파일은 `fetch` 로 받는 데 시간이 걸려, 받고 나서 `share` 를 부르면 이미 만료돼 있을 수 있다.
- **이 코드에서는**: 받은 `File` 을 `Map`(주소→파일)에 보관하고, 받는 사이 만료되어 `NotAllowedError` 가 나면 "준비됐어요 · 한 번 더 눌러 주세요"를 안내한다. 두 번째 누름은 이미 파일이 있으므로 **즉시** `share` 를 불러 허용이 유효하다. 작은 파일은 한 번에 끝난다.
- **다른 방법**: 클릭 즉시 공유할 수 있게 미리 받아 두기(메시지가 도착하면 백그라운드로 받기) — 메모리·데이터를 쓰므로 이번에는 하지 않았다.

### 3. 파일을 메모리에만, 지우면 같이 지우기

- 공유용 `File` 은 기기 메모리(`Map`)에만 두고 디스크·서버에 새로 남기지 않는다. 대화를 지우거나 완전 정리하면 `shareCache.clear()` 로 같이 비운다 — "기록이 남지 않는다"는 이 앱의 핵심 원칙을 지키기 위한 부분.

### 4. 시험에서 브라우저 기능을 가짜로 바꾸기

- 진짜 공유창은 자동화할 수 없다. `Page.addScriptToEvaluateOnNewDocument`(CDP)로 페이지가 뜨기 **전에** `navigator.share/canShare` 를 가짜로 심어, 앱이 **어떤 파일(이름·형식·크기·앞 8바이트)** 을 넘기는지 기록해 확인했다. 오류 흐름(취소·허용 만료·실패·형식 미지원)은 가짜가 `AbortError`/`NotAllowedError` 등을 던지게 해 시험했다.
- Windows 의 Edge 는 실제로 파일 공유를 지원하므로 "지원하지 않는 기기"는 `canShare` 가 false 를 돌려주는 것으로 흉내 냈다 — **환경이 이미 지원하는 기능의 부재는 심어서 만들어야 한다.**

## 시험에서 배운 것

- 첫 시험에서 **크게 보기 공유 버튼을 눌러도 아무 일이 없었다** — 버튼은 만들었지만 `onclick` 연결을 빠뜨렸다. 표시 시험(버튼이 보인다)만으로는 못 잡고 **동작 시험(눌렀더니 파일이 넘어간다)** 이 잡았다.
- 같은 데이터 주소(캐시 키)를 쓴 두 파일 때문에 "허용 만료" 시험이 캐시를 맞혀 거짓 실패했다 — 시험 데이터는 서로 겹치지 않게.
- 마지막에 서버를 거친 실제 파일(폰이 올린 PDF)로도 확인했다: 파일 주소를 `fetch` 한 바이트가 그대로 공유창으로 넘어간다.
