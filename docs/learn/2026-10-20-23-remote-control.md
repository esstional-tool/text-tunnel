# 원격 조종: 마우스·키보드 입력을 안전하게 전달하기

> 이슈 [#23](https://github.com/esstional-tool/text-tunnel/issues/23) · 2026-10-20
> 보기([노트](2026-10-20-17-remote-view.md)) → 알림([노트](2026-10-20-19-agent-alerts.md)) → PIN([노트](2026-10-20-21-remote-pin.md)) 다음 단계. 화면을 보는 것과 **남의 PC 에 입력을 넣는 것**은 위험의 크기가 다르다. 그래서 허용 단계를 따로 두고, 멈추는 수단을 먼저 만들었다.

## 허용이 겹겹이다

| 단계 | 누가 | 기본값 | 막는 곳 |
|---|---|---|---|
| ① 열쇠 | 짝 맺은 기기 | — | 서버 (열쇠 해시 방) |
| ② PIN | 보는 사람 | 필수 | **에이전트가 직접 확인** |
| ③ 조종 허용 | 조종당하는 PC 의 주인 | **꺼짐** | 서버(409) + 에이전트 |
| ④ 조종 켜기 | 보는 사람 | 꺼짐 | 서버(409) + 에이전트 |
| ⑤ 즉시 중지 | 주인 | — | Ctrl+Alt+F12 · 트레이 · `panic.now` |

하나라도 빠지면 입력은 버려진다. 서버를 한 번 더 믿지 않고 **에이전트도 자기가 PIN 을 확인해 준 사람(vid)인지** 다시 본다.

## 새로 쓴 기술

### 1. 입력 주입: `mouse_event` / `keybd_event`

- **개념**: Windows 는 프로그램이 마우스·키보드 입력을 "흉내 내어" 시스템에 넣는 API(`SendInput` 계열)를 준다. 받는 프로그램은 진짜 입력과 구별하지 못한다.
- **이 코드에서는**: 좌표는 화면 비율(0~1)로 받아 주 모니터의 실제 픽셀로 바꿔 `SetCursorPos` 후 버튼 플래그(왼쪽 `0x2/0x4`, 오른쪽 `0x8/0x10`, 가운데 `0x20/0x40`)를 보낸다. 브라우저의 버튼 번호(0 왼쪽·1 가운데·2 오른쪽)와 Windows 의 순서가 달라서 변환표가 필요했다. 휠은 브라우저 `deltaY` 100 = 한 칸이 Windows `WHEEL_DELTA` 120 이고 **부호가 반대**다(아래로 스크롤 = 브라우저 +, Windows −).
- **키보드**: `KeyboardEvent.code`(물리 키 위치)를 가상 키 코드(VK)로 바꿔 보낸다. 글자(`key`)가 아니라 **물리 키**를 보내므로 원격 PC 의 키보드 배열·한/영 상태를 그대로 따른다. 방향키·Home·Delete 같은 키는 "확장 키" 플래그가 필요하다.
- **한계**: UAC 창·잠금 화면·로그인 화면은 Windows 가 일반 프로세스의 입력을 막는다(UIPI/보안 데스크톱). 시험 환경이 입력 주입을 막으면 `SendInput` 이 접근 거부(오류 5)를 돌려준다 — 이번 시험에서 실제로 만난 상황.

### 2. 눌린 채 남는 키 방지

- **문제**: 키를 누른 뒤 "뗌" 이벤트가 오기 전에 연결이 끊기면 원격 PC 에서 그 키가 계속 눌린 상태(예: Ctrl 이 눌려 있어 모든 클릭이 Ctrl+클릭)가 된다.
- **해결**: 에이전트가 지금 눌려 있는 키·버튼을 집합으로 기억하고, 조종이 꺼질 때(보는 사람이 끔·주인이 허용 해제·연결 끊김·즉시 중지) **모두 뗀다**. 보는 화면도 캔버스가 포커스를 잃으면 눌린 키를 먼저 뗀다.

### 3. 전역 단축키 `RegisterHotKey`

- **개념**: 어느 창이 앞에 있든 특정 키 조합을 시스템에 등록해 두면 `WM_HOTKEY` 메시지로 알려 준다.
- **이 코드에서는**: 띠 창의 핸들에 Ctrl+Alt+F12(`NOREPEAT`)를 등록. 이 키는 **끄는 방향 전용**이라 오용돼도 위험이 줄어들 뿐이다. 다른 프로그램이 이미 쓰는 조합이면 등록이 실패하므로 `access.log` 에 경고를 남기고 트레이·`panic.now` 로 대체한다.
- **`panic.now` 파일**: 설정 폴더에 파일이 생기면 1초 안에 중지(원격 셸·스크립트용). 끄는 방향이라 파일 접근 권한이 곧 안전 위험이 되지 않는다.

### 4. 입력 묶음과 합치기 (coalescing)

- 마우스 이동은 초당 수십~수백 번 발생한다. 보는 화면은 16ms 마다 **묶어서** 한 번에 보내고, 이전 전송이 끝나기 전에 쌓인 이동은 **마지막 하나만** 남긴다(중간 위치는 의미 없음). 단, 클릭·키는 **순서가 중요**하므로 묶음은 한 번에 하나씩만 보내 순서를 지킨다.
- 서버는 한 묶음 120개, 본문 16KB, 보는 사람당 초당 600개(토큰 버킷)로 제한해 폭주를 막는다. 모양이 틀린 이벤트는 버린다.

### 5. 시험을 "무엇을 넣었을 것인가" 로 하기 (test sink)

- 입력 주입은 **시험이 곧 사고**가 될 수 있다(진짜 클릭이 엉뚱한 창에 간다). 에이전트에 `--input-sink 파일` 모드를 만들어 Win32 호출 대신 "`mouse 2 0`, `key 55 0`" 같은 줄을 파일에 적게 했다. 보는 화면 → 서버 → 에이전트 → 변환까지 전체 경로가 이 PC 를 건드리지 않고 검증된다.
- 진짜 주입은 따로 2부로 두고, **전용 표적 창**(숫자만 입력, 다른 창은 클릭하지 않음)에만 보내며 환경이 막으면 SKIP 한다.

## 시험에서 배운 것

- 실패 원인이 코드가 아니라 **시험 환경**일 수 있다: 화면 잠금/권한 때문에 입력이 거절됐다. "안 된다"를 곧바로 코드 버그로 보지 말고 환경(`OpenInputDesktop`, `SendInput` 오류 코드)을 먼저 확인했다.
- 보는 화면이 PIN 실패 때 "조종 허용" 상태까지 지워 버리는 버그를 UI 시험이 잡았다(허용 상태는 에이전트의 사실이므로 인증 결과와 분리해야 한다).

## 다음 공부 거리
