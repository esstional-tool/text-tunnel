# 앱에서 원격 허용 켜기: 에이전트 배포·상태 표시·자동 실행

> 이슈 [#30](https://github.com/esstional-tool/text-tunnel/issues/30) · 2026-10-21
> 원격조종을 다 만들었는데 "조종당할 PC 에서 어떻게 켜는지"가 앱 안에 없었다. 앱이 직접 해 줄 수 있는 것(안내·배포·상태)과 못 하는 것(다른 프로그램 입력)을 가르는 것이 핵심이었다.

## 어떤 문제였나

앱 메뉴의 "원격 화면 보기"는 **보는 쪽**이다. 켜는 쪽은 README 를 보고 직접 빌드·실행해야 했다. 브라우저는 보안상 다른 프로그램의 마우스·키보드를 대신 눌러 줄 수 없고 화면 공유도 매번 사용자가 창을 골라야 하므로, 에이전트(작은 프로그램)는 그대로 필요하다. 그래서 **앱은 "에이전트를 받아 켜는 길"을 한 화면에 모아 주고, 켜졌는지 실시간으로 알려 주는 역할**을 맡는다.

## 새로 쓴 기술

### 1. 서버가 파일을 "그 자리에서 만들어" 주기 (동적 zip)

- 확장 zip 은 서버 시작 때 한 번 만들었지만, 에이전트 zip 은 **요청마다 만든다**. 이유: 실행 명령(`run-agent.cmd`)에 **받는 사람이 접속한 서버 주소**(로컬이면 `http://localhost:8787`, Render 면 `https://…`)를 넣어야 하기 때문이다. 이미 있는 의존성 없는 `makeZip`(저장만 하는 최소 ZIP)을 재사용했다.
- **주입 방어**: 주소는 `Host` 헤더에서 오고 `.cmd` 파일 안에 들어간다. `a&calc.exe` 같은 값이 들어오면 명령 실행으로 이어질 수 있으므로 영문·숫자·`.` `:` `-` 만 허용하고, 아니면 주소를 아예 넣지 않는다(에이전트 기본값 사용). 외부 입력이 **실행 파일 안으로** 들어가는 모든 곳이 같은 종류의 위험이다.
- **비밀은 넣지 않는다**: 열쇠·PIN 은 zip 에 없고, 연결 코드(5분·한 번)는 화면에서 따로 만든다.

### 2. Windows 배치 파일의 함정 두 가지

- **줄 끝(CRLF)**: 개발 PC 에서는 CRLF 인 `build-agent.cmd` 가 리눅스 서버(Render)에서는 LF 다. LF-only 배치 파일은 `^`(줄 이음) 같은 문법이 깨질 수 있다. 서버가 zip 에 넣을 때 CRLF 로 바꾼다.
- **현재 폴더 탐색**: 환경에 따라 `cmd /c build-agent.cmd` 처럼 이름만 부르면 현재 폴더의 파일을 못 찾는다(`NoDefaultCurrentDirectoryInExePath`). `%~dp0`(이 배치 파일이 있는 폴더)로 전체 경로를 만들어 부른다. PowerShell 에서는 `.\run-agent.cmd` 처럼 `.\` 가 필요해서 안내 명령에 처음부터 넣었다.
- 이 두 가지는 **"압축을 풀어 그대로 빌드되는지"** 를 시험이 실제로 해 봐서 잡았다(처음 시험은 실패했다).

### 3. 시작 프로그램 등록: `HKCU\...\Run`

- **개념**: Windows 는 로그인할 때 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` 에 적힌 명령을 실행한다. 이 사용자에게만 적용되고 **관리자 권한이 필요 없다**. 값을 지우면 해제.
- **이 코드에서는**: `"exe" --server "<주소>" --config "<설정 폴더>"` 를 값으로 등록한다. 짝 코드·PIN 은 넣지 않는다(이미 저장된 열쇠·PIN 해시를 쓰므로). 트레이 메뉴 체크(`menu.Opening` 때 현재 상태를 읽음)와 `--autostart on|off` 가 같은 함수를 쓴다.
- **시험이 사용자 설정을 건드리지 않게**: 값 이름을 `--run-key-name` 으로 바꿀 수 있게 하고, 시험은 임의의 이름을 쓰고 끝에 반드시 지운다.

### 4. 실시간 상태 표시: "보는 사람"으로 입장해 알림만 받기

- 새 서버 기능 없이, 기존 `view/join` + SSE 의 `agent`(온라인/이름) 알림을 그대로 쓴다. 이 화면은 PIN 을 통과하지 않으므로 **화면·조종 알림은 받지 못하고**(서버가 인증된 사람에게만 보냄) "켜졌다/꺼졌다"만 안다 — 필요한 만큼만 아는 구조.

## 시험에서 배운 것

- zip 시험이 **구조(파일 목록·CRC)만이 아니라 동작(압축 풀어 빌드)** 까지 확인해서 배포 환경 차이(LF, 경로)를 잡았다. "만든 파일이 실제로 쓰이는가"를 시험해야 한다.
- 배치 파일/정규식 같은 **백슬래시가 많은 코드**는 셸 heredoc 을 거치면 글자가 바뀐다 — 파일로 쓰는 도구와 `String.fromCharCode(92)` 로 안전하게 만들었다(작업 중 세 번 겪음).

## 다음 공부 거리

- Windows 서비스/작업 스케줄러로 "로그인 전에도" 켜기(그러나 화면 캡처는 로그인한 세션에서만 가능)
- 코드 서명(SmartScreen 경고), MSI/MSIX 패키징 — 설치 파일 배포
- 에이전트 자동 업데이트(서버의 버전과 비교해 새 zip 안내)
